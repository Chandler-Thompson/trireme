# Trireme: Product Requirements

> **PRD generated by AI.** Drafted by the XO from the project's design decisions so the
> fleet can start work. Only the user changes this document. This notice stays until the
> user accepts or edits it.

## What Trireme is

An application for running a fleet of AI agents on a software project, and managing every
fleet from one place. Each seat in a fleet is one long-lived agent session with a written
role, working under a doctrine (`doctrine/`). The user directs everything through a chat
with an XO and a queue of decisions that need them.

The goal is that every actor, agent or human, is on the same page and moving in the same
direction.

## Who it is for

One person running several projects, each with its own fleet, who wants to see what every
fleet is doing, what it costs, and what is waiting on them, without reading agent
transcripts.

## Constraints

- **Harness-agnostic.** A seat runs under any harness through one adapter interface. The
  first adapter is the Claude Code CLI. No feature may depend on one vendor's tool.
- **Runs locally or on a server.** Double-click executables for Windows and Linux,
  optionally macOS, and a headless server mode with the GUI connecting to it remotely.
  Mobile apps and a public web interface are stretch goals.
- **Go server, web UI in a desktop shell (Wails).** Plain JavaScript in the UI.
- **Subscription usage windows are a real limit.** When a harness reports its usage window
  spent, the fleet pauses until the user resumes it.
- **Every UI action is also an API call**, so agents can do anything a user can.
- **Follows its own default doctrine**, including the full coding-standards profile.

## MVP

Already working (the hand-built core): the journal, fleet states (running, paused, stopped,
archived), the blockers queue, raisable project caps, seat turns with spend tracking,
compaction at a threshold, pausing on the usage window or the cap, a one-turn-at-a-time
scheduler, the XO chat, the API, `trireme-cli`, a browser UI, and a notification hook.

Still to build, in rough priority order:

1. **Task-board integration.** Blockers, consults, directives and tickets become items on a
   wood-fired-tasks board (or an equivalent), with Trireme as the screen over it. Today they
   live in Trireme's own database.
2. **Consult cards in the XO chat.** When the XO asks a seat something, an inline card
   ("Asking <project>'s Technical Lead…") appears in the chat and fills in when the answer
   arrives.
3. **The node-graph view.** Seats and tasks as movable, selectable nodes; edges from a seat
   to the task it holds, task dependencies, and temporary consult edges; features drawn as
   outlines around their tasks. Selecting a node shows its plain-language summary, spend and
   recent journal. One main view holds every running fleet's graph; a paused fleet greys
   out; a stopped fleet leaves the view but its information stays until it is archived.
4. **The PRD editor**, with the "PRD generated by AI" mark and an Accept action.
5. **Staffing requests**: the Producer files them with the Technical Lead's input side by
   side; the user accepts or declines in the blockers queue unless the project allows
   staffing at will.
6. **Git-Flow gates and labeled test builds** (`doctrine/modules/version-control/`).
7. **Release management**: which features are in which release, proposed by the Producer.
8. **The new-project form** (`doctrine/modules/new-project/`), every step doable without an
   agent.
9. **Doctrine as instance data**: the default ships as files; an instance holds modified or
   replacement doctrines, versioned with who, why and what changed.
10. **The desktop build**: Wails executables for Windows and Linux.

## Not in the MVP

More than one instance of a seat, a cheaper model translating agent text into plain text,
A/B testing of doctrine modules, a headless browser for UI tests, and a fleet that improves
its own application on a pinned release.

## Done means

For each item: it works through the UI and through the API, it has tests that fail when it
is broken, and QA has passed it against this PRD on a labeled test build.
